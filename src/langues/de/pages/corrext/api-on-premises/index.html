Häufige Fragen zu API und On-Premises

Bieten Sie eine API an, um die Übersetzung in unsere Tools zu integrieren?

Ja. Über eine REST-API rufen Sie den Übersetzungsmotor aus Ihren eigenen Systemen auf: Dokumentenmanagement, Intranet, Fachworkflows. Eine öffentlich zugängliche technische Dokumentation veröffentlichen wir nicht. Schnittstellenvereinbarung, Authentifizierung und Umfang der Aufrufe legen wir bei der Projektdefinition fest, gemeinsam mit Ihrer IT-Abteilung und unserem technischen Team.

Können wir die Lösung in unserer eigenen Infrastruktur betreiben?

Eine Installation on-premises ist für besonders sensible Umgebungen möglich, also wenn Ihre internen Regeln verlangen, dass nichts Ihr Netzwerk verlässt. Das ist ein eigenständiges Integrationsprojekt, das wir mit Ihrer IT-Abteilung planen: Architektur, Dimensionierung, Updates und Betrieb werden vor jeder Verpflichtung festgelegt.

Lassen sich unsere Zugriffsrechte aus SharePoint oder Active Directory übernehmen?

Das ist im Rahmen eines Integrationsprojekts vorgesehen. Die Zugriffsrechte lassen sich mit Ihrem Verzeichnisdienst und Ihren Dokumentablagen synchronisieren, damit alle in Corrext denselben Umfang vorfinden wie bei Ihnen. Diese Synchronisation ist keine Selfservice-Einstellung der Webanwendung: Sie wird mit Ihrer IT-Abteilung eingerichtet.

Können wir den Übersetzungsmotor als White Label in unser eigenes Produkt integrieren?

Das ist der Anwendungsfall von LegalTechs und juristischen Verlagen: Die Übersetzung wird zu einer Funktion Ihres Produkts, per API aufgerufen, ohne dass Ihre Nutzerinnen und Nutzer das Tool wechseln. Funktionsumfang, angezeigte Marke und Konditionen werden bei der Projektdefinition vertraglich festgelegt.

Wo werden die Daten bei einem API-Aufruf verarbeitet?

Es gelten dieselben Regeln wie in der Oberfläche: Die Speicherung erfolgt in jedem Fall auf Schweizer Servern. Die Verarbeitung erfolgt ausschliesslich in der Schweiz mit LexMachina oder im Modus Highly sensitive content, verfügbar für Deutsch, Französisch, Italienisch und Englisch. Die Drittmotoren DeepL Pro, Azure OpenAI GPT und Claude sind im Ausland gehostet und lösen den Pseudonymisierungshinweis aus, den Ihre Organisation festgelegt hat. Bei einer Installation on-premises ist der Verarbeitungsbereich Ihre eigene Infrastruktur.
